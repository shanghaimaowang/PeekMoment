# PeekMoment 后端开发说明

对应分工表 M1（账号与上传）、M3（内容互动）、M5（管理统计）。工程位于 `backend/`，SpringBoot 单体服务，同时服务小程序端和管理后台。本文档供小组回溯：环境搭建、约定、表设计、接口规划都在这里。

## 一、技术栈与版本

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17 | 已在 Temurin 17.0.20 验证编译 |
| SpringBoot | 3.2.5 | Web + Validation |
| MyBatis-Plus | 3.5.5 | 必须用 `mybatis-plus-spring-boot3-starter`，老 starter 与 Boot 3 不兼容 |
| MySQL | 8.x | utf8mb4，库名 `peekmoment` |
| jjwt | 0.12.5 | HS256 签名，双端 token 用 role 区分 |
| hutool-crypto | 5.8.27 | 仅用 BCrypt 存密码哈希，不引整套 Spring Security |
| Maven | 3.9+ | 编译命令 `mvn compile` 已验证 |

服务端口 8080。小程序请求不涉及跨域；管理后台是 Vite 开发服务器（5173），跨域已在 `WebConfig` 放开。

## 三、快速启动

1. 环境要求：JDK 17、Maven 3.9+、MySQL 8。
2. 建库建表：`mysql -uroot -p < src/main/resources/db/schema.sql`。
3. 修改 `application.yml` 中 `spring.datasource.password` 为本机密码。
4. 启动：工程目录下 `mvn spring-boot:run`，或 IDE 直接运行启动类。
5. 验证：浏览器访问 `http://localhost:8080/api/health`，应返回：

```json
{ "code": 0, "msg": "ok", "data": "PeekMoment backend 0.1.0 is running" }
```

6. 首次启动若 admin 表为空，自动创建演示管理员 admin / 123456（BCrypt 加密）。数据库未初始化时只打警告不阻断启动。

## 四、统一响应约定

所有接口返回 `{ code, msg, data }`，code = 0 表示成功，数字沿用 HTTP 语义：

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 400 | 参数错误（含校验失败、上传超限） |
| 401 | 未登录或 token 失效 |
| 403 | 已登录但角色不匹配、无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

service 层抛 `BusinessException` 即可，全局异常处理器负责转换，例如：

```java
if (content == null) {
    throw new BusinessException(ResultCode.NOT_FOUND, "动态不存在");
}
```

## 五、鉴权设计

双端共用一套 JWT 逻辑，token 的 `role` claim 区分身份：

| 端 | 登录接口（规划） | role | 拦截路径 |
| --- | --- | --- | --- |
| 小程序 | POST /api/mp/auth/login | user | /api/mp/** |
| 管理后台 | POST /api/admin/auth/login | admin | /api/admin/** |

- 请求头格式：`Authorization: Bearer <token>`，有效期 12 小时（yml 可调）。
- 角色不匹配返回 403，例如拿用户 token 访问管理接口。
- 游客可访问（GET 且路径匹配才放行）：`/api/mp/contents`、`/api/mp/search`、`/api/health`。发布、评分、评论等写操作必须登录。
- 业务代码取当前身份：`UserContext.currentUserId()`，无需再解析 token。

## 六、JSON 序列化约定

所有 `Long` 输出为字符串（`JacksonConfig` 统一处理）。JS 的 Number 只能安全表示 2^53 以内整数，前端一律按字符串处理 id、userId——与小程序开发文档的数据约定一致。前端传参时同样传字符串，Spring 自动转换。

## 七、数据库设计

10 张表，脚本见 `db/schema.sql`：

| 表 | 用途 | 关键设计 |
| --- | --- | --- |
| user | 小程序用户 | username 唯一；status 1 正常 0 禁用；软删除 |
| admin | 管理员 | username 唯一 |
| content | 动态 | title 选填 ≤40 字；body ≤1000 字；status 1 发布 2 待审核 3 下架；评分/评论数冗余列避免每次聚合；软删除 |
| tag | 标签 | name 唯一，≤12 字 |
| content_tag | 动态标签关联 | 联合主键，发布时标签不存在则新建 |
| media | 媒体附件 | kind 1 图 2 视频；sort_order 保证九宫格顺序 |
| rating | 评分 | (content_id, user_id) 唯一键 → 一人一评，重复评分即覆盖 |
| comment | 评论 | parent_id 为空是一级评论，非空是二级回复；status 2 为敏感词待审核 |
| friend | 好友关系 | status 0 待确认 1 已通过 2 已拒绝 |
| operation_log | 操作日志 | 记录管理端每次增删改，含 action 与目标 |

补充约定：时间列统一 DATETIME，前端展示用毫秒时间戳由接口层转换； MyBatis-Plus 已配置逻辑删除字段 `deleted`。

## 九、协作约定

1. 开发在 `feat/backend-*` 分支进行，PR 合并到 main，不直接改 main。
2. 骨架已完成（统一响应/异常/JWT/拦截器/建表），后续按上表认领模块，改动范围尽量不跨模块。
3. 新增接口遵循「controller 参数校验 → service 业务 → mapper 数据」分层；跨模块复用的查询下沉到 service 公共方法。
4. 联调对接方与替换位置见 `docs/小程序前端开发说明.md` 的接口联调分工一节：小程序端通过 `services/request.js` 的 `createRequest(baseUrl, readToken)` 注入服务地址与令牌。
5. 上传文件存本地 `uploads/` 目录（yml 配置），第 5 周云存储适配时仅替换存储实现，不改业务代码。
