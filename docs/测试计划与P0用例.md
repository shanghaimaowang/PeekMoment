# PeekMoment 第一周测试计划

本周验收从四个入口开始：游客打开广场、测试用户发布动态、管理员查询数据、小程序发布页选择媒体。P0 表示一旦失败，就会阻断演示主流程、写错数据或开放错误的访问权限。M7 复现问题并记录请求和结果，交由对应模块负责人修复；修复后用同一组输入回归。以下用例在独立的测试环境执行。

## 运行和交接

| 谁来验证 | 环境与步骤 | 可以得到的证据 |
| --- | --- | --- |
| M7、M3、M5 | 在项目根目录运行 `node --test tools/mock/server.test.mjs tools/qa/collection.test.mjs` | 每次启动一个新 Mock，按实际请求顺序执行集合中的脚本，检查 HTTP 状态、响应、令牌和动态 ID。 |
| M7、M1 | 进入 `backend` 运行 `mvn test`。JUnit 在随机端口启动 Spring Boot，默认测试配置使用独立 H2。MySQL 路径使用专门的空测试库，通过 Spring 数据源环境变量连接。 | `target/surefire-reports/` 记录对真实控制器和数据库的 HTTP 测试。审核状态仅在测试准备阶段用 SQL 设置。 |
| M6、M2 | 在根目录运行 `node --test frontend/miniprogram/tests/*.test.mjs`，微信权限与选图另用真机核对。 | 队列重试、顺序、清理和开发联调服务的测试记录。 |

### 在 Apifox 中运行

1. 启动本地 Mock（在仓库根目录执行 `node tools/mock/server.mjs`）或按项目 README 启动 Spring 服务。
2. 在 Apifox 中按 Postman 格式导入 [第一周接口集合](../tools/qa/peekmoment-week1.postman_collection.json)。在同一个本地测试环境里填写下表变量，按 01 到 12 依次请求。若用自动化场景，确保执行导入的前置和后置脚本。[Apifox 导入说明](https://docs.apifox.com/doc-5174528)
3. 04 会保存管理员令牌；08 会发布一条随机标题的 QA 动态并保存 ID；09 和 10 使用该 ID 核对两端看到的是同一条记录。建议每次运行选择独立测试库，避免 QA 帖子混入展示数据。

| Apifox 环境变量 | 内置 Mock | Spring 开发服务 |
| --- | --- | --- |
| `baseUrl` | `http://127.0.0.1:3100` | 默认 `http://127.0.0.1:8080` |
| `adminUsername` | `mock-admin` | `PEEK_ADMIN_USERNAME` |
| `adminPassword` | `mock-password` | `PEEK_ADMIN_PASSWORD` |
| `demoToken` | `mock-publisher` | `PEEK_DEMO_PUBLISH_TOKEN` |

集合版本为 Postman v2.1；结构已通过对应的官方 JSON Schema 校验。此次在本机执行了集合的 12 个请求和 21 条断言，使用 Node 对接 Mock，未在 Apifox 桌面端点选导入。

## 第一周 P0 用例

| 编号与负责人 | 前置条件和操作 | 通过依据 | 本次验证 |
| --- | --- | --- | --- |
| P0-01 · M1 | 启动服务，匿名访问健康检查及广场 | 健康状态为 ok；列表带页号、每页条数、总数和条目。 | Mock 通过；JUnit 覆盖相同入口。 |
| P0-02 · M5 | 错误口令登录；匿名查用户；用发布令牌查管理内容 | 均返回 401，错误体含非零 code、message、空 data。 | Mock 通过；JUnit 另覆盖管理员令牌不能用于发布。 |
| P0-03 · M3 | 使用发布身份提交含重复标签的动态，再查广场与后台 | 发布返回 201；服务器分配作者与 ID；标签去重且顺序保留；两端读回同一 ID。 | Mock 通过；JUnit 另核对媒体和正文。 |
| P0-04 · M3 | 匿名发布、提交空正文和空附件、页码取 0 | 分别得到 401、400、400。超长正文、冒用作者、临时媒体、本地脏数据不得写入。 | 前三项 Mock 通过；扩展输入和写入后复核由 JUnit 覆盖。 |
| P0-05 · M5 | 管理员登录后按一条一页查用户，按刚发布的标题查动态 | 返回正确条数、总数及动态；用户项无口令。相邻页面不重复，关键词中的下划线按字面匹配。 | 基本查询 Mock 通过；边界与排序 JUnit 覆盖。 |
| P0-06 · M3、M5 | 建立待审核、已隐藏两条记录，以游客和管理员身份分别查询 | 广场排除这两条，管理员可查到各自的状态。 | JUnit 已编写，真实库结果按下方记录。 |
| P0-07 · M2 | 游客进发布页后登录，再进个人中心；开发联调模式浏览、发布 | 登录状态可识别；翻页按服务端结果更新；写入带当前开发令牌，错误可见。 | 本地登录和浏览器预览结果见[小程序开发说明](./小程序前端开发说明.md)；联调服务测试通过。 |
| P0-08 · M6 | 在发布页选图；模拟暂时失败、永久失败、离开页面 | 队列并发最多 3 个、顺序稳定；暂时失败按预算重试；手动重试复用已成功项；离开页面停止分配新任务。 | 小程序服务层自动测试通过；微信相册和压缩效果待真机复核。 |

### 验证记录与后续排期

本机已通过 Mock 的请求回读、集合的 12 个场景、小程序的联调与上传服务测试。Spring 端的七个 HTTP 用例位于 [WeekOneHttpTest.java](../backend/src/test/java/cn/peekmoment/WeekOneHttpTest.java)。本次环境尚未取得 Maven 依赖，JUnit 与 MySQL 8 的执行结果待 CI 回填。Mock 的结果只对应 Mock 实现。

| 周次 | 进入测试的条件 | 当周优先回归 |
| --- | --- | --- |
| 第 2 周 | 微信登录、正式上传和存储接口就绪 | 账号切换、文件真实回读、弱网重试、发布失败回收；在真机记录微信版本和机型。 |
| 第 3–4 周 | 互动和管理接口就绪 | 评论/评分持久化、非作者编辑拒绝、审核状态流转；每次修复同步补充可重放用例。 |
| 第 5–6 周 | 摘要、发布部署和演示数据就绪 | 摘要失败降级、敏感词误判、全流程回归和两次演示彩排。 |

缺陷记录包含用例编号、版本、环境、最短复现步骤、预期及实际响应、负责人和复测结果。令牌与密码在共享记录中隐去。两项加分能力的样本和验收依据见[敏感词与摘要预研](./测试预研-敏感词与摘要.md)。
