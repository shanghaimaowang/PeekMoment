# 敏感词与动态摘要预研

第一周需要确定两个接口以后怎么接、什么情况值得交给人处理。下面的词条和示例均为测试用的虚构数据。

## 敏感词识别

用三个词条 `纸飞机`、`纸飞机票`、`AB票` 做了六次本地对照。对正文执行 JavaScript 的 `normalize('NFKC')`，按词表顺序用 `includes` 逐项检查，得到以下结果。这个小样本用于确定预期匹配语义。

| 输入 | 实测命中 | 设计影响 |
| --- | --- | --- |
| 发现纸飞机票 | 纸飞机、纸飞机票 | 保留重叠命中；在审核队列里合成同一条任务。 |
| 领取ＡＢ票 | AB票 | 全角英文字母归一化后可命中。 |
| 分享校园照片 | 无 | 作为普通内容的对照。 |
| 纸 飞 机 | 无 | 词中插入空格会漏检；把是否忽略空格作为单独策略评估。 |
| 请勿发布纸飞机广告 | 纸飞机 | 劝阻语句也会命中，需保留原文给审核人判断。 |
| 今天领到ab票 | 无 | 大小写折叠需要显式规则。 |

建议第二周在 Java 服务中用 Trie 构建 Aho–Corasick 自动机。词典更新时重新构建后整体替换；每条动态记录词典版本，并按规则标记“待审核”。用以上六个样本验收同一套匹配语义，再记录大词典下每千条耗时。规范化可能改变字符数；审核端首版可以展示原文与命中词，原文高亮需先完成位置映射。算法资料见 [pyahocorasick 项目文档](https://pyahocorasick.readthedocs.io/en/latest/)。

## 大模型摘要

选取纯文字校园动态作为第一批样本。例如输入“周四下午三点在南区体育馆有羽毛球赛，可以现场报名”，人工参考摘要为“周四15点，南区体育馆举办可现场报名的羽毛球赛”。对这条样本检查三个事实：时间、地点、报名方式。纯图片或空正文直接显示原内容。

后续建议由后端在动态发布成功后异步生成摘要。输入只取经允许用于处理的正文，去掉用户标识、账户信息和媒体文件。输出按纯文本渲染，限制长度；调用超时、返回空串或内容已编辑时继续展示新正文。以内容版本绑定摘要，避免较早的生成结果覆盖编辑后的内容。模型的响应无需任何业务写权限。输出处理可参照 [OWASP 的模型输出处理建议](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/)。

| 后续验证样本 | 观察项 | 验收方式 |
| --- | --- | --- |
| 含时间、地点、否定词的活动通知 | 编造或删掉关键信息 | 用人工标注的事实表逐项核对，记录遗漏或矛盾个数。 |
| 短正文与纯媒体 | 冗余摘要、无意义调用 | 短文可直接展示；纯媒体跳过生成。 |
| 服务超时、空输出、非法返回 | 发布是否仍然成功 | 注入失败，检查发布结果与页面正文。 |
| 请求期间编辑或删除 | 过期摘要覆盖、已删内容重新出现 | 延迟返回旧结果，核对内容版本及删除状态。 |

第一周已完成词典样本实测和摘要验收设计。摘要样例是人工参考，模型质量、响应时间和费用留到选定服务后用同一组样本测量。
